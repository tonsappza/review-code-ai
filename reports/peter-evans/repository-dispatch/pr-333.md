## Summary

This PR updates the multiline `client-payload` README example so free-text env values (`MY_PROJECT`, `MY_CONTAINER`, `SLACK_DEPLOY_MSG`) are emitted via `toJSON()` instead of quoted string interpolation. That is the right fix for broken or injectable JSON when values contain quotes, backslashes, or newlines. The change is documentation-only and aligns with the intent of the branch name.

The updated `deployment` fields are correct, but the example still has problems that can mislead copy-paste users: invalid JSON syntax (trailing comma) and mixed escaping patterns in the same block.

## Findings

### [severity: major] — Trailing comma makes the multiline example invalid JSON
- **File:** `README.md` (lines 149–150)
- **Issue:** After `deploy_msg`, the example keeps a trailing comma before the closing `}` of `deployment`. Standard JSON parsers reject that, so a user who copies the block verbatim may send malformed `client-payload` and see dispatch/API failures unrelated to `toJSON`.
- **Suggestion:** Remove the trailing comma after the last property:

```json
"deploy_msg": ${{ toJSON(env.SLACK_DEPLOY_MSG) }}
```

(no comma before `}`)

---

### [severity: minor] — Same example still uses unsafe interpolation for `repo` fields
- **File:** `README.md` (lines 142–144)
- **Issue:** `deployment` now uses `toJSON()`, but `repo.name`, `repo.branch`, and `repo.tag` still use `"${{ ... }}"`. Output/env values with `"`, `\`, or newlines can break JSON or alter structure the same way the old `deployment` lines did.
- **Suggestion:** Apply the same pattern for consistency and safety, e.g. `"name": ${{ toJSON(github.repository) }}`, or document why those values are assumed safe.

---

### [severity: suggestion] — Inconsistent `toJson` / `toJSON` casing in README
- **File:** `README.md` (lines 116, 123 vs 147–149)
- **Issue:** Earlier examples use `toJson`; the changed lines use `toJSON`. GitHub Actions expressions are generally case-insensitive for this function, but mixed casing in one doc is noisy.
- **Suggestion:** Pick one form (prefer matching lines 116/123: `toJson`) across the multiline example.

---

### [severity: suggestion] — Other README examples still show the old pattern
- **File:** `README.md` (line 59)
- **Issue:** The quick-start example still builds JSON with `"${{ github.ref }}"` style interpolation. Not introduced by this PR, but readers may not connect it with the multiline fix.
- **Suggestion:** Optional follow-up: add a short note near line 59 or link to the multiline section when values are user-controlled free text.
