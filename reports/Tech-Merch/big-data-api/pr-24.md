## Summary

PR นี้เพิ่มข้อมูล **เลขที่คำขอ (BookNumber / RequestNo)** และ **พฤติการณ์ (Circumstance)** ให้ Bank Upload list/detail โดย join ผ่าน `FormRequestBankID` และแก้ Cassandra mapping ด้วย `ExplicitColumns()` + `[Ignore]` บน `RequestNo` ซึ่งแก้ปัญหา undefined column ได้ถูกทาง

จุดที่น่ากังวลหลักคือ **performance regression (N+1 + query ซ้ำ)** ใน `GetBankUploadListAsync` และการเลือก `BookNumber` จาก `FirstOrDefault()` ทั้งที่ `GetFormRequestBankByRequestBankID` คืนหลายแถวได้ นอกจากนี้ endpoint อื่นที่คืน `BankUploadListResponse` ยังไม่ได้ enrich ทำให้ contract ไม่สม่ำเสมอ

## Findings

### [severity: major] — N+1 Cassandra queries ใน list endpoint
- **File:** `bigdataAPI/Services/SP_BankUploadService.cs` (`GetBankUploadListAsync`)
- **Issue:** เปลี่ยนจาก `Select` เป็น `foreach` ที่ `await GetBookNumberByFormRequestBankID` และ `await GetCircumstanceByFormRequestBankID` ต่อแถว แต่ละ helper สร้าง `new FormRequestBankRepository()` และเรียก `GetFormRequestBankByRequestBankID` (มี `AllowFiltering()`) อีกครั้ง — สูงสุด **2 query ต่อแถวในหน้าเดียว** (เช่น page size 20 ≈ 40 round-trips) เทียบกับเดิมที่ไม่มี lookup เลย
- **Suggestion:** รวบ `FormRequestBankID` ที่ไม่ซ้ำในหน้านั้น แล้ว fetch ครั้งเดียว (หรือ helper เดียวที่คืนทั้ง `BookNumber` และ `Circumstance`) ใส่ `Dictionary<Guid, FormRequestBank>` แล้ว map ใน loop; inject `IFormRequestBankRepository` แทน `new` ใน private method

### [severity: major] — Query ซ้ำสองครั้งต่อแถวสำหรับ ID เดียวกัน
- **File:** `bigdataAPI/Services/SP_BankUploadService.cs` (helpers ~L1166+ ใน diff)
- **Issue:** ใน loop เดียวเรียกทั้ง `GetBookNumberByFormRequestBankID` และ `GetCircumstanceByFormRequestBankID` ซึ่งทั้งคู่เรียก `GetFormRequestBankByRequestBankID` ซ้ำกับ payload เดิม
- **Suggestion:** รวมเป็น `GetFormRequestBankContext(Guid id)` ที่ fetch ครั้งเดียวแล้วคืน `(bookNumber, circumstance)` หรือคืน `FormRequestBank` ที่เลือกแล้ว

### [severity: major] — BookNumber อาจมาจากแถวผิดเมื่อมีหลาย FormRequestBank
- **File:** `bigdataAPI/Services/SP_BankUploadService.cs` (`GetBookNumberByFormRequestBankID`)
- **Issue:** `GetFormRequestBankByRequestBankID` คืน `List<FormRequestBank>` แต่ `GetBookNumber` ใช้ `FirstOrDefault()` โดยไม่กรอง ในขณะที่ `GetCircumstance` เลือกแถวที่มี `Circumstance` / `RequestDetail` ก่อน — logic ไม่สอดคล้องกัน อาจได้เลขที่คำขอจากแถวที่ไม่ใช่แถวหลัก
- **Suggestion:** ใช้เกณฑ์เลือกแถวเดียวกันทั้งสอง field (เช่นแถว active ล่าสุด หรือแถวที่มี `BookNumber` ไม่ว่าง) ให้ตรงกับที่ `FormRequestBankService` ใช้อยู่แล้ว

### [severity: minor] — `RequestNo` บน entity ไม่ถูก hydrate จาก DB
- **File:** `bigdataAPI/Models/Entity/SP_BankUploadModel.cs`, `bigdataAPI/Services/SP_BankUploadService.cs`
- **Issue:** `RequestNo` มี `[Ignore]` และไม่มี column ใน mapping ดังนั้น `bookNumber = x.RequestNo` / `bankUpload.RequestNo` จาก Cassandra จะเป็น `null` เสมอ — fallback ไป FormRequestBank เกือบทุกครั้ง; ชื่อ property สับสนกับ `BookNumber` ใน response
- **Suggestion:** ตัด dead path หรือตั้งชื่อชัดว่าเป็น in-memory only; ถ้าต้องการ cache บน upload ให้ map column จริงแทน `[Ignore]`

### [severity: minor] — API response ไม่สม่ำเสมอระหว่าง endpoints
- **File:** `bigdataAPI/Services/SP_BankUploadService.cs` (`SearchBankUploadListAsync` — ไม่อยู่ใน diff)
- **Issue:** เพิ่ม `RequestNo`, `BookNumber`, `Circumstance`, `FormRequestBankID` ใน `GetBankUploadListAsync` / `GetBankUploadByIDAsync` แต่ `SearchBankUploadListAsync` ยัง map แบบเดิม — client ที่ใช้ search vs list จะได้ shape ต่างกัน
- **Suggestion:** enrich แบบเดียวกันใน search (หรือ helper ร่วม `MapToBankUploadListResponse`)

### [severity: minor] — กลืน exception ทั้งหมดใน helper
- **File:** `bigdataAPI/Services/SP_BankUploadService.cs` (`GetBookNumberByFormRequestBankID`, `GetCircumstanceByFormRequestBankID`)

- **Suggestion:** log อย่างน้อยระดับ warning พร้อม `formRequestBankID`; อย่า catch แบบกว้างถ้าไม่จำเป็น

### [severity: suggestion] — `RequestDetail` เป็น fallback ของ Circumstance

- **Issue:** `return formRequestBank?.Circumstance ?? formRequestBank?.RequestDetail` อาจส่งข้อความยาว/รายละเอียดคำขอแทน “พฤติการณ์” ถ้า product ต้องการเฉพาะ `Circumstance`
- **Suggestion:** ยืนยันกับ UX/requirement; ถ้าไม่ต้องการ fallback ให้คืนเฉพาะ `Circumstance`

### [severity: suggestion] — import ที่อาจไม่ใช้ + attribute ซ้ำ namespace

## Test plan

- เรียก **Bank Upload list** (`GetBankUploadListAsync`) กับแถวที่มี `FormRequestBankID` — ตรวจว่า `RequestNo`, `BookNumber`, `Circumstance` ตรงกับ Form Request Bank จริง
- ทดสอบแถวที่ **ไม่มี** `FormRequestBankID` และที่ lookup ล้มเหลว (ID ไม่มีใน DB) — fields ควรเป็น `null` โดยไม่ error ทั้ง response
- ทดสอบ **detail** (`GetBankUploadByIDAsync`) — ค่าเดียวกับ list สำหรับ record เดียวกัน
- เรียก **SearchBankUploadListAsync** (ถ้า dashboard ใช้) — ยืนยันว่าต้องการ fields ใหม่หรือยอมรับความต่าง
- ค้นหา Form Request Bank ด้วย keyword ที่เป็น **เลขที่คำขอ (BookNumber)** — ต้องเจอใน `FormRequestBankRepository` filter
- โหลด/บันทึก `BankUpload` หลัง `ExplicitColumns()` — ไม่มี Cassandra error `undefined column requestno` และข้อมูลเดิมยังอ่าน/เขียนได้ครบ
- **Performance:** วัด latency ของ list กับ page size สูงสุด (เช่น 50 แถวที่มี `FormRequestBankID` ทุกแถว) เทียบก่อน merge — ควรไม่เกิน SLA
- กรณี **หลายแถว FormRequestBank** ต่อ `RequestBankID` เดียว — ยืนยันเลขที่คำขอและพฤติการณ์มาจากแถวที่ product กำหนด ไม่ใช่แถวสุ่มจาก `FirstOrDefault()`
